# MODE-01 Project Inception

## Goal
Decide whether a project should be built and define the smallest valuable, supportable release.

## Required roles
Product or user research, strategy or commercial, architecture, open-source selection, security or privacy when relevant, delivery or operations, and finance for material cost.

## Procedure
1. Define target users, jobs, painful current alternatives, constraints, and measurable outcome.
2. Separate verified demand, assumed demand, and unavailable market evidence.
3. Inventory existing products, internal capability, framework features, open-source systems, and workflow combinations.
4. When interface assumptions affect adoption or feasibility, activate [ui-ux-quality.md](ui-ux-quality.md) to define users, critical journeys, platform conventions, accessibility needs, and prototype evidence without prematurely designing the full product.
5. Test feasibility across data, integration, security, operations, legal or license, and cost.
6. Compare buy, reuse, configure, integrate, minimal build, and do nothing.
7. Define an MVP with explicit exclusions, dependency assumptions, cost envelope, and validation plan.
8. Produce GO, CONDITIONAL_GO, DEFER, or NO_BUILD.

## Evidence
Primary user or market sources when available; source and license identity for candidates; prototype or technical spike only when necessary; cost ranges with assumptions.

## Stop condition
A decision and bounded MVP are supported, or named missing evidence makes the decision premature. Do not start implementation without separate authorization.

## Output
Use assets/project-plan-template.md and assets/open-source-comparison-template.md.
