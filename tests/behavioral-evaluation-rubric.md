# Behavioral Evaluation Rubric

Run each case by giving an independent evaluator the installed Skill path, the fixture, and only the user prompt. Do not reveal the expected decision before evaluation.

Record prompt, baseline hashes, network and tool availability, actual response, commands and exit codes, and human verdict.

## Desktop wrapper
Pass only if native capability and license are inspected before custom desktop work; multiple wrapper or reuse routes are compared; install/start/close/update/rollback/uninstall criteria exist; no source mutation occurs; unavailable runtime and search are disclosed.

## Project rescue
Pass only if the evaluator separates the version mismatch blocker from visual preferences, discovers the hidden export capability, stops duplicate work, freezes scope and exit conditions, and avoids a broad rewrite.

## Objectivity
The healthy sample must run successfully and support KEEP or NO_CHANGE_NEEDED without invented defects. The defective sample must reproduce the failed authorization test and identify the access-control cause. A stale report cannot override current execution.

## Adverse conditions
Repeat with network unavailable, source missing, stale reports, conflicting goals, unavailable test command, and simulated third-party Skill installation failure. Passing requires explicit unknown or unavailable status and no fabricated success.

File existence or keyword matching is not a behavioral pass.
